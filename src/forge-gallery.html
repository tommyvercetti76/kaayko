Tap the card

One engine, one profile, one subject.

Every render here came from the same command: forge engine render minimalist-tshirt --profile madhubani with a subject sentence and a seed. The engine carries the style rules (folk fills, double-contour keylines, no scenery); the profile carries the model and the palette; the subject is the only thing that changes. Flip any card and the exact subject is there to copy.

Tap the card

Every render writes its own paperwork.

Next to each PNG the engine leaves a directive sidecar: the full positive prompt, the negative list (over ninety phrases, from “photorealistic” to “artist signature glyph”), the 60/30/10 palette it was held to, the seed, the steps, the guidance, and an audit of which rules were applied. A run can be reproduced or argued with a year later. Four seeds render in one pass, 60.8% faster than one at a time.

Tap the card

Guarded runs, and a cut-out for free.

A guarded run checks the result against the prompt’s own claims before it is kept: a giraffe whose neck is shorter than its legs fails, a body that came out as a silhouette fails, a signature the model invented fails. Two of the Indian candidates for this page were dropped for a fake signature. Each keeper also gets a transparent PNG, the subject lifted off the paper, ready for print work.

Tap the card

On your machine, under a licence you can read.

Forge runs on Apple Silicon with no cloud, no key and no upload. These eight were rendered with FLUX.1 [dev], whose licence is non-commercial, so they are shown here and not sold. Forge’s default today is FLUX.2 klein 4B under Apache 2.0, and the same command reproduces the series on it. The model is a tool; the licence decides what the output is for.

What Forge is

Forge is an open-source, local-first generative-AI workstation for Apple Silicon. It is MIT licensed and written in Python 3.11+, and it runs entirely on the machine in front of you — no cloud round trip, no rented GPU, no API key, no subscription, and nothing uploaded anywhere. Every image on this page was produced on-device.

Why local-first matters

Running a model on your own hardware changes what you are allowed to do with it. Your prompts and your outputs never leave the machine, so there is no third party logging what you made or deciding after the fact that you should not have made it. It also means the thing keeps working when an API is deprecated, a price changes, or a service goes down. The trade is speed and convenience against ownership, and Forge takes the ownership side of that trade deliberately.

What changed this week

Forge now composes the printed cards behind kaay.link: one layout for every card (a title, one line, what the code does, the address, the code alone on one paper panel), error correction M and a two-module quiet zone so a phone reads the code off a screen at 400 px, artwork staged on its own edge colour with feathered edges. Every run writes a new folder and a contact sheet; nothing is overwritten and the grade is on the sheet. The Baithak poster was rendered by FLUX.2 klein 4B, deliberately without people, because the model draws them badly and an honest render beats a flattering one. The three cards, the run sheet and the raw render are in the repository's gallery folder.

What these renders demonstrate

The gallery is not a highlight reel. It exists to show what the pipeline actually produces at a given point in the project, including the runs that did not clear the bar. The test suite has 284 tests, and a multi-seed mflux run came in 60.8% faster than the previous implementation. Those numbers are published whether or not they flatter the project — when a ship threshold was written down before a run and the result came in under it, the verdict goes next to the methodology rather than getting quietly dropped. A benchmark you can only pass is not a benchmark.
